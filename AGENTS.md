# Project instructions

## Project

Frontend of a mfin.uz SaaS (signed documents, Didox-like). Vue 3 + TypeScript SPA, Vite, Bun, vue-router 4, pinia, vee-validate + zod, vue-i18n, openapi-fetch.
The backend is a SEPARATE repo (FastAPI) and replaces an old Go API. This repo is being migrated to the new backend. UI/UX must not change unless I say so; the data/API layer is what changes.

- Commit = stage the working tree AS IS with explicit paths (never `git add -A`). Never revert or rewrite files to "split" commits. Show `git diff --cached --stat` and wait for my "go".

- Never put secrets, tokens, `.env` contents or personal data into memory files, reports, mocks or commits. Do not stage or touch `AGENTS.md`, `.opencode/` or `.audit/`.
- Keep changes scoped to the task; reuse existing patterns; do not overwrite another session's in-progress work.

## Architecture rules

- Feature slices with 4 layers: domain / application / infrastructure / presentation, enforced by eslint-plugin-boundaries. Do not break boundaries; do not add boundary exceptions without asking.
- All HTTP lives in `features/*/infrastructure/*Repository.ts`, bound only in `src/app/di/container.ts`. Generated API types stay inside `infrastructure/`; domain and UI never import them.
- Central client: `src/shared/infrastructure/api/client.ts`. No raw fetch/XHR/axios in app code.
- UI components must keep receiving the shapes they receive today; differences between old and new API are absorbed by repositories/mappers (adapter layer), not by components.
- Generated client: `openapi/openapi.json` -> `bun run api:generate` -> `src/shared/infrastructure/api/schema.ts`. Never edit schema.ts by hand.

## New backend facts (verify against .audit before relying)

- Errors: `{"error": {"code","message","problems?"}}`; request-validation 422 uses FastAPI `{"detail":[...]}`. UI text is mapped from machine codes on the frontend (i18n).
- Auth: access token kept in memory only; refresh token is an httpOnly cookie (`credentials: 'include'`). Refresh, logout and switch-tenant require header `X-Requested-With: XMLHttpRequest`. Do not decode the JWT; use `expires_in` and `/identity/me`.
- Mutating document endpoints (create draft, send, sign) need an `Idempotency-Key` header.
- Money values are decimal strings. Lists use cursor pagination.
- Workspace model became tenants (`switch-tenant`); no select-workspace step.
